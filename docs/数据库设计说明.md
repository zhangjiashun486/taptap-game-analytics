# TapTap 游戏数据分析与智能推荐平台 —— 数据库设计说明（V1.0）

> 阶段：需求分解（系统工程路径第 3 步）  
> 目标：把需求文档中的功能需求落成可开发的表结构，并指导“数据入库”步骤。

## 一、总体说明

- 数据库：虚拟机 MySQL **5.6.35**（192.168.100.101:3306，SQLyog 管理），库名 `taptap_course`，字符集 `utf8mb4`；
- 建表脚本：`sql/schema.sql`（兼容 MySQL 5.6；JSON 字段以 TEXT 存储）；
- 数据来源：`data/game_ids.json`（10,221 个游戏 ID）+ `data/raw/taptap_details.jsonl`（10,219 款完整详情 JSON）；
- 设计原则：游戏/标签/用户/行为分表；聚类按“运行批次”保存，支持多轮对比；原始 JSON 保留在文件中，数据库存结构化字段。

## 二、表结构与关系

| 表 | 作用 | 关键关系 |
| --- | --- | --- |
| t_user | 用户（含管理员） | 行为、问答日志的外键 |
| t_game | 游戏主表（评分/热度/关注/评论/厂商/简介等） | 标签、行为、聚类结果的外键 |
| t_tag / t_game_tag | 标签及游戏-标签多对多 | 游戏 ↔ 标签 |
| t_behavior | 用户行为（浏览/收藏/点赞/玩过/评分） | 用户、游戏 |
| t_cluster_run | 聚类运行批次（K、轮廓系数、参数） | 聚类结果/簇画像 |
| t_cluster_result | 每款游戏属于哪个簇 | 运行批次、游戏 |
| t_cluster_meta | 簇命名、规模、关键词、簇中心、代表游戏 | 运行批次 |
| t_crawl_log | 采集日志（状态/条数/时间） | 管理端可视化数据源 |
| t_qa_log | 问答日志（问题/意图/答案/模式） | 管理端问答统计 |
| t_recommend_log | 推荐日志（得分/理由） | 推荐效果统计（可选） |

主要关系：

```
t_user 1 ── n t_behavior n ── 1 t_game
t_game n ── n t_tag   (通过 t_game_tag)
t_cluster_run 1 ── n t_cluster_result n ── 1 t_game
t_cluster_run 1 ── n t_cluster_meta
```

## 三、数据入库计划（下一步）

1. 读取 `data/raw/taptap_details.jsonl`（10,219 行）；
2. 解析字段写入 `t_game`：标题、评分、最新版评分、评论数、关注数、热度、愿望单、简介、厂商、发行时间、图标 URL；
3. 解析 `tags` 写入 `t_tag` + `t_game_tag`；
4. 清洗规则：缺失评分保留为空；游戏 ID 去重；标签去空格；
5. 统计入库结果（成功/失败/缺失），写入 `t_crawl_log`，供管理端“数据采集可视化”使用。

## 四、待确认

1. MySQL root 密码（或让用户手动执行建库脚本）；
2. 是否需要把 `raw` JSON 也入库（当前方案：文件保留原始数据，数据库存结构化字段）；
3. 价格字段：详情接口未返回，后续如需要可从榜单接口补充（当前允许为空）。

## 五、执行方式

```bash
mysql -u root -p < sql/schema.sql
```

执行成功后会创建 `taptap_course` 库及 10 张表。
