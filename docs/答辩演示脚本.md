# 答辩演示脚本（约 8~10 分钟）

**项目**：TapTap 游戏数据分析与智能推荐平台  
**演示顺序**：讲背景（1 分钟）→ 架构与数据（2 分钟）→ 用户端演示（2 分钟）→ 管理端演示（3 分钟）→ 总结与展望（1 分钟）

---

# 一、开场（1 分钟）

> “我们的选题是 TapTap 游戏数据分析与智能推荐平台。TapTap 上游戏数量巨大，玩家找游戏难、平台缺少内容生态的量化分析。
> 我们做了三件事：① 用爬虫采集了 10,219 款游戏数据；② 用 K-Means 做聚类分析，形成游戏画像；③ 做了一个 Web 平台，支持浏览、收藏、推荐和问答，并有管理端可视化大屏。”

---

# 二、架构与数据（2 分钟）

**架构一句话**：

> “系统分三层：Python 负责采集和分析（FastAPI 服务）、Java 负责业务服务（唯一对外出口）、Vue 做两个前端（用户端 8001、管理端 8002）。数据存 MySQL，原始数据同时归档到 HDFS。”

**数据链路一句话**：

> “爬虫先用榜单和标签‘滚雪球’找到全部游戏 ID（10,221 个），再逐款抓详情（10,219 条、163MB），清洗后入库 MySQL，然后用 6 个特征做 K-Means 聚类，分成热门大作、口碑神作、小众佳作、预约爆款、争议待改进五类。”

演示要点（可打开文档/截图）：

- 采集规模：10,219 款 / 607 标签 / 42,629 条标签关系；
- 聚类：K=5、轮廓系数 0.2355；
- 数据合规：公开数据、低频访问、断点续传、只存元数据。

---

# 三、用户端演示（2 分钟）

**操作步骤**：

1. 打开 `http://localhost:8001` → 未登录自动跳登录页；
2. 用 `demo_user_01 / 123456` 登录 → 首页（10,219 款游戏，按关注/评分排序）；
3. 搜索“原神” → 进入《原神》详情 → 点击收藏；
4. 打开推荐页 → 展示“因为你收藏了《原神》…”的推荐和理由；
5. 打开问答页 → 输入“预约最高的 5 款游戏” → Java 先查 MySQL，DeepSeek 组织回答，失败时自动回退规则结果；
6. 打开个人中心 → 展示收藏/玩过/评分记录。

**讲解词**：

> “推荐不是简单的热门榜，而是读取用户行为后，找同簇、同标签的游戏；新用户没有行为时会走冷启动，推荐高分且有真实评论量的游戏。”

---

# 四、管理端演示（3 分钟）

**操作步骤**：

1. 打开 `http://localhost:8002` → 用 `admin / 123456` 登录；
2. **总览**：展示 10,219 款游戏、22 个用户、825 条行为、7 次问答、5 条采集日志；
3. **采集监控**：展示采集日志，包括 HDFS 归档 163.9MB 的记录；
4. **聚类分析**：展示簇规模饼图和簇画像（关键词、代表游戏）；
5. **用户行为**：展示行为分布饼图、近 7 天趋势、热门游戏/活跃用户；
6. **问答统计**：展示意图分布和最近问答记录。

**讲解词**：

> “管理端不是静态页面，所有数据都来自真实数据库；采集日志里能看到 HDFS 两段式归档记录，聚类页面对应我们 K-Means 的结果。”

---

# 五、总结与展望（1 分钟）

> “目前系统已经完成主流程闭环：采集 1 万多款游戏、聚类分析、个性化推荐、数据问答、管理端可视化。
> 后续可以扩展：① 在现有 DeepSeek 问答基础上升级向量检索 RAG；② 增加更多数据源做多平台对比；③ 用 Spark/Hive 处理更大规模数据。”

# 六、可能被问到的问题（提前准备）

| 问题 | 回答要点 |
| --- | --- |
| 数据从哪来？合法吗？ | TapTap 公开页面/接口，低频访问，只存游戏元数据，未下载游戏内容，仅教学用途 |
| 为什么用聚类而不是分类？ | 没有历史标注数据，只能无监督聚类 |
| K 怎么选的？ | 肘部法 + 轮廓系数 + 业务可解释性，最终 K=5 |
| 推荐怎么做的？ | 读取用户行为 → 同簇 +2 分、同标签 +1 分 → 排序 → 附推荐理由 |
| 断点续传怎么做？ | 每爬完一个标签/每 25 条详情写 state.json/progress.json，中断可续 |
| HDFS 起什么作用？ | 原始数据归档（本地 + HDFS 两段式），符合大数据存储规范 |
| FastAPI 的作用？ | 把 Python 采集/分析能力封装成 HTTP 接口，供 Java 调用；前端不直连 Python |
| 系统还有什么不足？ | DeepSeek 已接入并支持规则回退，但尚未引入向量数据库；评论情感分析等仍可继续扩展 |
