**项目**：TapTap 游戏数据分析与智能推荐平台（HunuProjec2）  
**阶段**：项目开发 5.1（Python 数据分析）  
**数据**：10,219 款游戏（其中 8,340 款有评分参与聚类，1,879 款未评分/下架单独标记）

**代码**：`data_server/jobs/cluster_games_v2.py`  
**结果**：`t_cluster_run` / `t_cluster_result` / `t_cluster_meta`，导出 `data/output/game_clusters.csv`、`cluster_summary.json`

# 1. 什么是聚类分析

聚类是**无监督学习**：不预先给标准答案，让算法根据数据本身的相似度自动分组。

- 分类：有标签、有标准答案（如“动作/射击/角色扮演”）；
- 聚类：没有标签，算法自己发现哪些游戏“长得像”。

本项目没有历史标注数据，因此采用聚类分析，把游戏按特征分成若干可解释的群体（簇），用于游戏画像、个性化推荐和管理端可视化。

# 2. 整体流程

```
读取 MySQL 数据（10,219 款）
      ↓
筛选：有评分的 8,340 款参与聚类；无评分的 1,879 款标记为“未评分/下架”
      ↓
特征工程：为每款游戏构造 6 个数值特征
      ↓
标准化：把不同量纲的特征换算到同一尺度（z 分数）
      ↓
KMeans 聚类：评估 K=2~8，最终确定 K=5
      ↓
簇画像与命名：热门大作 / 口碑神作 / 小众佳作 / 预约爆款 / 争议待改进
      ↓
结果落库：t_cluster_run / t_cluster_result / t_cluster_meta
```

# 3. 使用的 6 个特征

| 序号 | 特征 | 计算方式 | 业务含义 |
| --- | --- | --- | --- |
| 1 | 评分 | 原始评分（0~10） | 游戏质量口碑 |
| 2 | 评论量 | log1p(评论数) | 讨论热度 |
| 3 | 关注量 | log1p(关注数) | 人气规模 |
| 4 | 预约量 | log1p(预约数) | 未上线游戏的期待度 |
| 5 | 愿望单 | log1p(愿望单数) | “想玩”程度 |
| 6 | 评论关注比 | log1p(评论数) − log1p(关注数) | 讨论活跃度/粘性 |

**为什么要取 log（log1p = ln(1+x)）**：关注数动辄千万，评分只有 0~10，直接计算距离时“关注数”会完全主导结果。取 log 压缩大数值，让各特征影响力更均衡（同时避免 0 取对数报错，故用 log1p）。

# 4. 什么是标准化坐标（z 分数）

**定义**：

```
z = (特征值 − 全体平均) ÷ 标准差
```

含义：

- `z = 0`：处于全体平均水平；
- `z = +1`：比平均高 1 个标准差（“高出一个档次”）；
- `z = −1`：比平均低 1 个标准差；
- 标准化后，所有特征的平均值为 0、标准差为 1，可以直接比较、计算距离。

**全体 8,340 款游戏的基准值**：

| 特征 | 处理后的平均 | 标准差 | 原始量级参考 |
| --- | --- | --- | --- |
| 评分 | 7.68 | 1.54 | +1σ ≈ 9.22 分；−1σ ≈ 6.15 分 |
| log 评论 | 5.50 | 1.99 | 平均≈243 条；+1σ≈1,786 条；−1σ≈32 条 |
| log 关注 | 10.55 | 2.28 | 平均≈38,145；+1σ≈372,313；−1σ≈3,907 |
| log 预约 | 3.34 | 4.62 | 平均≈27；+1σ≈2,866 |
| log 愿望单 | 2.33 | 2.00 | 平均≈9；+1σ≈75 |
| 评论关注比 | −5.05 | 1.04 | +1σ≈−4.01；−1σ≈−6.09 |

## 4.1 逐步计算示例：《蛋仔派对》

原始数据：评分 7.8、评论 50,590、关注 38,701,637、预约 0、愿望单 570。

| 特征 | 原始值 | 取 log 后 | 全体平均 | 标准差 | 计算 | z 值 |
| --- | --- | --- | --- | --- | --- | --- |
| 评分 | 7.8 | — | 7.68 | 1.54 | (7.8−7.68)/1.54 | **0.08** |
| 评论 | 50,590 | 10.83 | 5.50 | 1.99 | (10.83−5.50)/1.99 | **2.68** |
| 关注 | 38,701,637 | 17.47 | 10.55 | 2.28 | (17.47−10.55)/2.28 | **3.04** |
| 预约 | 0 | 0 | 3.34 | 4.62 | (0−3.34)/4.62 | **−0.72** |
| 愿望单 | 570 | 6.35 | 2.33 | 2.00 | (6.35−2.33)/2.00 | **2.01** |
| 评论关注比 | — | 10.83−17.47 = −6.64 | −5.05 | 1.04 | (−6.64+5.05)/1.04 | **−1.53** |

**《蛋仔派对》的标准化坐标 = [0.08, 2.68, 3.04, −0.72, 2.01, −1.53]**

读法：它的评论、关注、愿望单远高于平均水平（z 明显为正），预约低于平均（z 为负），评分几乎等于平均（0.08）。

# 5. KMeans 算法原理

## 5.1 初始中心如何确定（k-means++）

最初的中心**不是平均值，而是从游戏数据中选出的真实游戏点**。scikit-learn 默认使用 k-means++：

1. 随机选择第 1 个中心（一款真实游戏）；
2. 计算每款游戏到“已选中心最近一个”的距离，**距离越大越容易被选为下一个中心**（概率正比于距离平方），使中心尽量分散；
3. 重复直到选满 K 个中心。

用 `random_state=42` 复现出的一次初始中心如下（均为真实游戏）：

| 初始中心 | 游戏 | 标准化坐标 |
| --- | --- | --- |
| 1 | 快乐连连消 | [1.12, −1.51, −1.53, 0.71, −1.17, 0.45] |
| 2 | 对不起，我是警察 | [0.01, −0.22, 0.32, −0.72, 1.50, −1.13] |
| 3 | 萌萌塔 | [−0.18, 1.06, 0.47, −0.72, −0.82, 0.99] |
| 4 | 深空矿工 | [−0.83, −0.66, −0.39, −0.72, −0.36, −0.42] |
| 5 | 双子 | [1.18, 2.44, 1.49, −0.72, 2.31, 1.41] |

参数说明：

- `n_init=10`：做 10 次不同的初始化，各自跑完，取 SSE（簇内误差平方和）最小的一次；
- `random_state=42`：固定随机种子，保证每次运行结果一致、可复现。

## 5.2 迭代过程：分配与更新

```
① 对每款游戏，计算它到 K 个中心的欧氏距离，归入最近的中心；
② 对每个簇，重新计算中心 = 该簇所有游戏坐标的平均值（标准化空间）；
③ 中心移动后，重新分配；
④ 重复 ②③，直到中心几乎不再变化（收敛）。
```

欧氏距离公式（6 维同理）：

```
d = √[(特征1差)² + (特征2差)² + … + (特征6差)²]
```

举例：某游戏坐标为 A，两个中心分别为 C1、C2，若 d(A,C1) < d(A,C2)，则该游戏归入 C1 簇。

**初始中心与最终中心的区别**：

| | 初始中心 | 最终中心 |
| --- | --- | --- |
| 是不是真实游戏 | 是（算法选出的游戏点） | 否（一群游戏的平均坐标，虚拟点） |
| 例子 | 《双子》[1.18, 2.44, 1.49, −0.72, 2.31, 1.41] | 热门大作中心 [0.06, 1.42, 1.25, −0.62, 1.33, 0.00] |

# 6. 如何确定 K 值（簇的数量）

测试 K=2~8，分别计算 SSE（越小越紧凑）与轮廓系数（越大越分离）：

| K | SSE | 轮廓系数 |
| --- | --- | --- |
| 2 | 35,228 | 0.2713 |
| 3 | 28,738 | 0.2732 |
| 4 | 24,099 | 0.2525 |
| 5 | 21,615 | 0.2355 |
| 6 | 19,670 | 0.2333 |
| 7 | 18,086 | 0.2375 |
| 8 | 16,878 | 0.2244 |

选择依据：

1. **肘部法**：K 从 2 增加到 5 时 SSE 下降明显，之后下降趋缓；
2. **轮廓系数**：K=2/3 略高，但分组过粗，业务价值低；
3. **业务可解释性**：K=5 能形成“热门大作/口碑神作/小众佳作/预约爆款/争议待改进”五类清晰画像。

综合以上，最终确定 **K=5**（保留 run_id=1 的 K=2 结果作为算法对比）。

## 8.3 如何读这些数字

以“热门大作”中心 `[0.06, 1.42, 1.25, −0.62, 1.33, 0.00]` 为例：

| 维度 | 数值 | 解读 |
| --- | --- | --- |
| 评分 | +0.06 | 与全体平均（7.68）几乎一致 |
| 评论 | +1.42 | 讨论热度显著高于平均（还原约 4,144 条，全体平均约 243 条） |
| 关注 | +1.25 | 人气规模显著高于平均（还原约 65 万，全体平均约 3.8 万） |
| 预约 | −0.62 | 预约偏低（该簇多为已上线游戏） |
| 愿望单 | +1.33 | 想玩人数偏高（还原约 147，全体平均约 9） |
| 评论关注比 | 0.00 | 讨论活跃度处于平均水平 |

一句话：**热度高、讨论多、想要的人多，但评分只是普通水平** —— 因此命名为“热门大作”。

其他簇同理：

- **预约爆款**：预约 +1.47（最高）、评分 +0.57 → 未上线但期待度高；
- **口碑神作**：评分 +0.25 略高、其他维度接近平均 → 稳定好评；
- **小众佳作**：关注 −1.45、评论 −1.07（人气低），评论关注比 +1.14（最高）→ 人少但讨论意愿强；
- **争议/待改进**：评分 −1.58 → 口碑明显偏低。

## 8.4 为什么“热门大作关注均值”看起来不高？

以簇 0（热门大作）的**关注数**为例，不同统计口径差别很大：

| 统计口径 | 数值 | 说明 |
| --- | --- | --- |
| 算术平均 | 1,587,562 | 直接平均，容易被王者荣耀（9,829 万）这类超大数据拉高 |
| 中位数 | 564,379 | 排在中间位置的值，不受极端值影响 |
| 几何平均（本说明的“关注均值”） | 652,337 | log 空间平均后还原，衡量“典型量级” |

聚类距离计算使用的是**标准化后的算术平均**；文档中展示的“还原值”是几何平均，两者口径不同，差异属于正常现象。

# 10. 聚类结果的应用

1. **个性化推荐**：用户收藏某游戏后，推荐“同簇 + 同标签”的其他游戏，并给出理由（如“因为你收藏了《蛋仔派对》，同类热门大作推荐……”）；
2. **管理端可视化**：聚类规模分布、中心雷达图、簇画像、代表游戏列表（对应原型“聚类分析”页面）；
3. **数据问答**：支持“口碑神作有哪些”“预约爆款 Top10”等问题；
4. **内容分析**：比较各簇的评分/热度结构，输出游戏内容生态结论。

# 12. 常见问题（FAQ）

**Q1：聚类结果有标准答案吗？**  
没有。聚类是无监督方法，换特征、换 K 会得到不同划分；只要结果可复现、可解释、对业务有用即为合理。

**Q2：为什么 K=2 的轮廓系数更高，却选 K=5？**  
K=2 只能分出“热门/非热门”，业务价值低；K=5 结合了肘部法拐点与可解释性，能形成五类有意义的游戏画像。

**Q3：为什么有些还原值是 0 或很小？**  
预约、愿望单等字段大量游戏为 0（数据稀疏），log/标准化还原后接近 0 属于正常现象。

**Q4：标签为什么没有作为聚类特征？**  
第一版（run_id=1）曾加入 Top30 标签特征，导致 K=2 且簇含义模糊；第二版改用 6 个数值特征，聚类更稳定。标签仍用于**簇关键词与推荐**。

**Q5：每次运行结果会变吗？**  
固定 `random_state=42` 且数据不变时结果一致；数据更新或参数调整后会生成新的 run_id，可用 t_cluster_run 对比。

**Q6：未评分的 1,879 款游戏怎么处理？**  
不参与聚类，cluster_id 记为 −1，名称“未评分/下架”，保证每款游戏都有归属。

# 13. 名词表

| 名词 | 含义 |
| --- | --- |
| 特征 | 描述样本的数值，如评分、评论数 |
| 标准化（z 分数） | (值 − 平均) / 标准差，使不同特征可比 |
| 欧氏距离 | 多维空间中两点“直线距离”，用于判断相似度 |
| 簇 / 中心 | 一组相似样本；该组的平均坐标（虚拟代表点） |
| SSE | 簇内误差平方和，越小表示簇内越紧凑 |
| 轮廓系数 | 衡量“簇内紧、簇间远”，取值 −1~1，越大越好 |
| 肘部法 | 通过 SSE 下降速度选 K 的经验方法 |
| 收敛 | 中心不再明显移动，迭代结束 |
